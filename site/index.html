How it works

From install to verdict, in one command.

No dashboard login, no account required to start. Point it at a folder and read the output.

01 · discover

Find every skill

Auto-discovers installed skills across Claude Code, Cursor, Gemini, Codex, and project-local folders — including ones nobody remembers installing.

02 · scan

Read what it does

Static analysis of SKILL.md, bundled scripts, and tool manifests. No execution, nothing runs, nothing leaves your machine.

03 · score

Get a stated reason

Every finding ships with a confidence score and a plain-language reason — not a bare pass/fail.

04 · gate

Fail CI on critical

SARIF output for GitHub Code Scanning, plus a pre-commit hook that blocks only on critical findings.

Detection rules

What it actually catches.

Every rule runs in every tier, including Free. You're not paying to unlock detection — you're paying for scale.

RULE · 01

Prompt injection

Hidden instructions embedded in tool descriptions or skill metadata that redirect agent behavior.

RULE · 02

Credential exfiltration

Code paths that read local environment variables, keys, or credentials and send them outbound.

RULE · 03

Concealed instructions

Directives hidden in HTML comments, frontmatter, or auto-exec hooks not visible on a normal read.

RULE · 04

Unicode obfuscation

Invisible or lookalike characters used to smuggle text past a human reviewer.

RULE · 05

Over-broad permissions

Requested capability scope that exceeds what the stated function needs.

RULE · 06

Post-approval drift

A skill silently changed after it was reviewed and approved — the rug-pull pattern.

RULE · 07

Untrusted external install

Install steps that pull code from sources outside the skill's own declared origin.

RULE · 08

Opaque payloads

Bundled binaries or archives whose contents can't be statically reviewed at all.

RULE · 09

Loose parameter schema

Tool parameters typed broadly enough to accept arbitrary, unvalidated input.

Why local

Nothing leaves your machine.

Most agent-security tools require an API token and a hosted analysis service — meaning the contents of your skills are sent somewhere before you find out if they're safe. ryzek doesn't.

That matters more here than in most tooling categories: the files you're scanning are, by definition, the ones you haven't verified yet.

Why this exists

Built by people who watched the ecosystem outgrow its own trust model.

R

Agent skills run with the full permissions of the agent they extend — filesystem, network, credentials — and the ecosystem is growing faster than anyone is reviewing what gets installed. That gap is where ryzek started: a scanner built to answer one plain question before code runs, not after.

It's built local-first on purpose. A tool that checks whether something is safe to trust shouldn't itself require you to trust a server you can't see.

FAQ

Common questions.

Does ryzek send my code anywhere?
No. Scanning is fully local — nothing about the skills you scan leaves your machine. Telemetry is anonymous, usage-only, and off by default.
Which agent tools does it work with?
Claude Code, Cursor, Gemini CLI, Codex, and any project using SKILL.md or standard MCP tool manifests. ryzek discover finds installs across all of them automatically.
Is the Free tier actually usable, or a crippled demo?
All 54 detection rules run in Free. The only limit is 20 scans a month — you're capped by volume, not by which threats it can catch.
Can I read the source before I trust it?
Yes — the full source is public on GitHub under BUSL-1.1. You can audit exactly what it does; the license restricts commercial resale, not reading or self-hosting for your own use.
Do I need Node.js installed?
Currently yes, via npx. Standalone binaries with no runtime dependency are on the roadmap.
