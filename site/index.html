Every finding tells you how much to trust it

The documented failure mode of security scanners is noise: loose rules flag everything, people stop reading the output, the tool gets uninstalled. So every finding carries a confidence score and an explanation of why that score is what it is.

Catching the rug pull

Tool-poisoning attacks don't look malicious at install time. A skill passes review, gets approved, and then its permissions quietly change — while the agent keeps trusting the original approval. A single-snapshot scanner cannot catch this by definition: nothing is wrong with either snapshot in isolation.

# Monday — reviewed, approved, baseline recorded Scanned 1 skill(s): 1 clean, 0 flagged. # Thursday — vendor pushes an update. Not a heuristic — a verified diff.

A detection rate you can reproduce

Most scanners assert quality. This one publishes a number, the corpus it was measured on, and the misses.

$npm run benchmark

Read this before quoting the number

Nine samples is a small corpus. 100% means ryzek catches these known, published attack patterns. It says nothing about novel attacks, and it is not a generalised detection rate.

The first run scored 85.7%. The single miss — a credential-capture hook buried in YAML frontmatter — exposed three real bugs, including a parser that silently dropped nested frontmatter so the payload was invisible to every rule. All fixed. The misses are the useful output; the score is a side effect.

What it doesn't do

Stated up front. A security tool that oversells itself is worse than no security tool at all.

It's a pattern matcher

Independent research in 2026 bypassed every public skill scanner tested, in under an hour. ryzek is in that same structural category. It raises the floor against known patterns — it is not a guarantee against a motivated attacker.

Static analysis only

It reads manifests and bundles. It doesn't watch runtime behaviour. It complements runtime guardrails — it doesn't replace them.

No binary or archive inspection

Payloads hidden inside compiled or archived files are a documented bypass and aren't covered yet.

Drift needs a second scan

The first scan can only establish a baseline. There's nothing to compare against yet.

6 of 10 AST10 categories

Isolation, governance, and cross-platform reuse are runtime or organisational concerns a static scanner can't assess.

It's new

No large user base yet. The reproducible benchmark is what exists in place of a track record.
