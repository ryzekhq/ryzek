Changelog

What changed, and when.

Every release, with the reasoning behind it. Detection rules are listed individually so you can see exactly what a version added.

v1.3.0 · unreleased
Twelve rules to fifty-four

The largest release so far. Detection expands past skills into the MCP configuration layer, into the agent's own context, and across the whole toolset at once — 42 new rules, taking the set from 12 to 54.

MCP configuration scanning — seven new rules covering auto-approve settings, unpinned remote servers, credentials stored as literal values, known-vulnerable pinned versions, package impersonation, over-broad launch commands, and STDIO injection surface. MCP server definitions now load as tools, so a server entry goes through the same rules as a skill manifest instead of a separate code path.

MCP STDIO injection surface — in April 2026, OX Security disclosed that MCP's STDIO transport passes configuration values into subprocess execution without sanitisation, across every official SDK. Anthropic reviewed it and declined to change the protocol, stating sanitisation is the developer's responsibility. ryzek now checks whether your configuration sits on that pattern, and grades by whether an actual injection path is present rather than flagging every stdio server.

Known-CVE version matching — pinned versions are checked against a hand-verified advisory set. Patched versions produce no output at all.

Agent-safety rules — markdown image beacons, forged tool results, memory poisoning, deferred triggers, chain injection, confused-deputy patterns, system-prompt extraction and context-history access. These target the agent's reasoning rather than its filesystem, which is where the newer attacks live.

Rules that need the whole toolset — homoglyph and duplicate tool names, and toolset mutation, compare tools against each other rather than reading one in isolation. shadow-mcp-discovery finds MCP servers configured outside the project; it reads client configs in your home directory, so it is opt-in behind --shadow rather than running silently.

Fewer false positives — the manifest loader treated any JSON file with a name as an agent tool, which meant package.json and package-lock.json were scanned as tools on every npm project. Package-manager and tooling files are now skipped.
