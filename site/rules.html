OWASP MCP Top 10 coverage

    
Every rule is mapped to the OWASP MCP Top 10 (MCP01:2025–MCP10:2025,
       currently in beta). Ten categories, 54 rules — several rules map to more
       than one category, and several categories have many rules. Depth per risk is
       the number that matters, not the total.

Two of those rows are worth a note. The published
       coverage matrix for this framework rates a pre-deploy scanner as
       no coverage on MCP07 and MCP09 — authentication and shadow servers
       are assumed to need a gateway or an identity layer. Ryzek covers both
       statically. MCP08 is genuinely thin at one rule, and it should be:
       audit and telemetry is a logging problem, not a scanner's.

  






  

    
What's next

    
Fifty rules today. The engine turns a new rule into a data entry rather than
       a function, so the next one is minutes rather than an afternoon. These are
       what's actually queued — not a wish list.

    
    
      
  • Live server inspection. Start the server in a sandbox and read the
          tool descriptions the agent actually sees, not just the config file.
    • 
      
  • OAuth misconfiguration. Overly broad scopes, missing PKCE, wildcard
          redirect URIs.
    • 
      
  • Permissive CORS on HTTP-transport servers.
    • 
      
  • Provenance verification. Sigstore and SLSA attestation checked at
          install, not after.
    • 
      
  • SBOM output. CycloneDX, covering tools and actions as well as
          dependencies.
    • 
      
  • Attack paths. Multi-hop chains, and the smallest set of servers you
          could remove to break all of them.
    •
